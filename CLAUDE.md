# Project: griffel (screenshot annotation tool and whiteboard)

A home-made take on Epic Pen / Tekapoint for Linux. A screenshot of the monitor is frozen fullscreen, and you mark it up with shapes and text. Without a screenshot it is a whiteboard for sketches and diagrams.

## Environment
- Developed and tested on Arch Linux, X11 (no Wayland), herbstluftwm + sxhkd, Alacritty (config in TOML)
- Python 3 + PySide6 (Qt6). On Arch the dependencies come from pacman (`pyside6`). No new dependencies (pip or otherwise) without asking
- GUI tests run in a separate invisible X server (`tests/gui/`: Xvfb + herbstluftwm + sxhkd, driven by xdotool, screenshots in `tests/gui/out/` that you can look at). Use it instead of the real desktop

## Architecture
- Package `griffel` in `src/griffel/` (all modules flat in it, file names below are relative to it), built via `pyproject.toml` (setuptools, entry point `griffel = griffel.app:main`, rofi theme as package data in `data/`, found via `importlib.resources`). Imports are absolute: `from griffel.canvas import Canvas`, `from griffel import history`. The version is only in `griffel.__version__` (`--version`). From the source folder it starts via `run.py` (puts `src/` into `sys.path`); `python -m griffel` works with `PYTHONPATH=src`. Plan: `docs/notes/plan-pakete.md`
- The screenshot is taken with `QScreen.grabWindow(0)` before the window appears
- Shown in a frameless, monitor-sized window (`QGraphicsView`) with a `QGraphicsScene`, bypassing the window manager (`Qt.X11BypassWindowManagerHint`). Keyboard via normal focus with `activateWindow()` (for bypass windows Qt sets the X focus directly), no keyboard grab, so global sxhkd hotkeys keep working; the scene is activated by hand (`Canvas.show_overlay()`). On close, `wm.restore_focus()` gives the focus to the window herbstluftwm currently has focused (`herbstclient attr clients.focus.winid`, then `xdotool windowfocus`). Focus follows the mouse like `focus_follows_mouse` in herbstluftwm: if the overlay loses the focus (e.g. through a hotkey) while the mouse is over it, it takes it back after `FOCUS_RETRY_MS` (`changeEvent`), likewise when the mouse enters (`enterEvent`) or clicks into the image; not during a rofi prompt (`asking`)
- Selection via Qt's built-in selection (`ItemIsSelectable`), also several elements: `selected_elements()` (all, bottom to top), `selected_element()` only for exactly one (handles, editing text). Changes to several are one undo step: `MoveItemCommand` takes lists, `property_command(changes)` (one or many setters), deleting via `beginMacro`. Order (front/back) = stacking order of the scene at equal zValue, changed via `ReorderCommand`/`apply_order` (`stackBefore`), never via zValue; `RemoveItemCommand` puts the element back in its old place on undo. Rotating (Q / Shift+Q, `rotate_selected`): around the middle, so `pos` moves along; position+angle via `PoseMixin.pose()`/`set_pose()` (bound method, so undo merges steps); `drag_handle` must handle rotated elements (local coordinates, `mapToScene`/`mapFromScene`). Blur and markers do not rotate. Rotate handle: `rotate_handle()` (circle above the top edge, not for line/arrow), `handle_at()` then returns `ROTATE_HANDLE`, state `rotating`, follows the mouse freely (no snapping); Shift on the handle is deliberately unused (maybe aligning later). `Canvas.update_bars()` shows the values of the selection in the bar. Property changes as `PropertyCommand`. Frames and handles are drawn by `Canvas.drawForeground` (never in the export); every element provides `handle_points()`, `drag_handle()`, `geometry()`/`set_geometry()` for it. New element types need these four methods
- Shapes are `ShapeElement` (`elements.py`, subclass of `QGraphicsPathItem`): fixed `id`, `tool`, `points` in local coordinates, `color`, `width`, for rectangles `radius` (corner radius, for new ones from `[rect] radius` or `radius_board`, missing when loading = 8). Position only via `pos()`/`rotation()`, path built by `rebuild()` from the values. Text is a `TextElement` (subclass of `QGraphicsTextItem`, brings cursor and input): `id`, `color`, `font_size`, `font_kind` ("normal"/"mono", Alt+V, saved as `"font": "mono"`, font via `elements.text_font`, family from `[text] mono_font` or Alacritty, `colors.load_terminal_font`), `edit_state()` for `EditTextCommand`, `start_editing()`/`stop_editing()`. Both element types have `color` and `set_color()`
- Tools in `tools.py`: `Tool` enum, geometry in `shape_path()`, icon for the tool bar in `tool_icon()`. Which key selects which tool is set by `[tools] order` (position i) and the action `tool_i` in the key table. New tools only appear automatically if the config has no order of its own. More tools than keys are not reachable by keyboard. Select (W), marker (C) and blur (Z) have fixed places (`FIXED_TOOLS`), not part of `[tools] order`
- Messages and prompts in `notify.py`: `notify()` via `notify-send` (dunst), `ask()` via `rofi -dmenu` (fuzzy search, theme `data/griffel.rasi` + `~/.config/rofi/colors.rasi`). In the canvas only via `Canvas.report()` (message) and `Canvas.ask()` (takes the focus back afterwards in screenshot mode), never `toast.show_message()` directly. Chosen via `[ui] messages = "dunst" | "toast"`, `dialogs = "rofi" | "qt"`; if the program is missing or fails, Qt fallback (`ui.Toast`, `QMessageBox`). Without a screen (`QT_QPA_PLATFORM=offscreen`, tests) never external
- Base color and shown color: elements store their base color (`color`, from the palette). Shown is `elements.shown_color()`: the scene adapts it via `Canvas.adapt_color`, darkened on a light whiteboard background (`colors.adapt_color`, contrast `LIGHT_CONTRAST` 3.0, own values in `[colors.light]`), otherwise unchanged. Elements recompute it in `refresh_color()` (when inserted into the scene via `itemChange`, after a background change via `Canvas.refresh_colors()`, which also adapts the color bar). Comparisons (e.g. active color in the bar) always with the base color. Selection frame and handles take whichever of bar foreground/background has more contrast to the whiteboard (`Canvas.selection_colors()`)
- UI colors: `ui.Theme` (background, foreground, opacity, accent, heading), default from Alacritty `colors.primary`, changeable in `[ui]`. New UI elements take their colors from the theme, never hard-coded. Sizes: give measurements for a 1080 px screen height and multiply with `ui.ui_scale(screen)` (bar `set_scale`, toast, overview), so nothing is tiny on 4K. Active field in the bar: inverted (tool, size) or a light ring (color), overall size `MainBar.SIZE`
- Own config: `~/.config/griffel/config.toml`, read in `config.py`, template in `config.example.toml`. Color values come from Alacritty (`colors.py`); selection, order and start value of colors and tools from the own config
- Settings in `settings.py`: defaults and limits as constants, `Settings` reads everything from the config at startup that does not change during the session (size steps, palette, theme, step widths …); the canvas accesses it via `self.settings`. What changes (tool, color, step, whiteboard background) belongs to the canvas and starts with `settings.default_*`. New config value = `settings.py` + `config.example.toml` (+ a case in `tests/test_settings.py`). The git hook updates the developer's own `~/.config/griffel/config.toml` before each commit (`scripts/sync_config.py`: template + own values, backup `config.toml.bak`; preview by hand with `--dry-run`). Enable the hook with `git config core.hooksPath scripts/git-hooks` (again after a fresh clone)
- Keys centrally in `keymap.py`: `DEFAULT_KEYS` (action → key), overrides from `[keys]` in the config (old spelling `[tools] keys` still works), handlers in `Canvas.actions`. New key = exactly these three places, plus a description in `shortcuts.DESCRIPTIONS` for the key overview (?, `ui.HelpPanel`, drawn by hand: left keyboard half with column stagger like a split keyboard (`shortcuts.KEYBOARD_COLUMNS`, `ui.KEYBOARD_STAGGER`, tool icon or short word from `shortcuts.SHORT`, Shift below), color swatches, size dots, plus lists without the keys in the picture, spread over three columns of about equal length; data from `shortcuts.overview()`, keys in lower case, scaled with the screen height (measurements for 1080 px, overall size `HelpPanel.SIZE`); `tests/test_settings.py` checks that none is missing). The overview shows the actual bindings including `[keys]` and only what applies in the current mode. Keys match exactly (Shift+T is not T). Esc is fixed in the code
- Image elements: `ImageElement` (`elements.py`, own `QGraphicsItem`): `image`, `size` (display), handles with a fixed aspect ratio, `to_dict` with a Base64 PNG; `set_color`/`refresh_color` do nothing, color/size changes skip images. All element types: `canvas.ELEMENT_CLASSES` (register new types there and in `document.ELEMENT_TYPES`)
- Passing on a copied image editably: `copy_image()` in screenshot mode puts a private file (`rich_copy_path()`, `$XDG_RUNTIME_DIR/griffel/clipboard.json`) next to the finished PNG (clipboard, for other programs): image element of the crop + elements in it + SHA-256 of the PNG. `clipboard_elements()` uses it if the PNG in the clipboard matches, otherwise a plain image element. Caution: xclip as owner answers every type request with its content; read only via Qt or after checking TARGETS (`export.data_from_clipboard`)
- Copying elements: `OutputMixin.copy_selection_or_image` / `paste_elements` / `duplicate_selected` / `insert_copies`; clipboard with its own data type `application/x-griffel-elements` (JSON of the `to_dict`s) via `export.copy_data_to_clipboard`/`data_from_clipboard` (xclip, so it stays pasteable in another window after quitting)
- Export in `export.py`: render the scene without the bar (area = screenshot rectangle), clipboard via `xclip` (keeps the image after quitting), fallback Qt clipboard
- Canvas files: `app.py` is only the startup (`main`, `grab_screen`; options file, `--board`, `--last`), the `Canvas` lives in `canvas.py` (setup, state, tool/color/size, bars, keys). Its other methods are spread over mixins it inherits from: `canvas_input.py` (`InputMixin`: mouse, text input, handles/`drawForeground`, mouse wheel, hjkl, deleting), `canvas_board.py` (`BoardMixin`: pan/zoom the whiteboard view, background, title, prompt on close), `canvas_output.py` (`OutputMixin`: render, copy, save, export, `report`, `ask`), `canvas_history.py` (`HistoryMixin`: history), `canvas_crop.py` (`CropMixin`: crop, `output_area()` returns area and size for every render and save in screenshot mode, `paint_crop` from `drawForeground`; selectable in the select tool by clicking its edge, `crop_selected`, drag handles and edge, Esc removes it, Del clears the area as soon as no element is selected (even without clicking the crop): `clear_crop_area` fills the raw image inside with the most common color around it (`surrounding_color`) (`set_background_image`, one undo step together with removing the crop)), `canvas_pointer.py` (`PointerMixin`: own mouse cursor from `make_cursor`, `refresh_cursor()` after changing tool/color/size/zoom/background; spotlight and magnifier in `paint_pointer`, called from `drawForeground`) (split see `docs/notes/plan-aufteilung.md`; `tests/test_document.py` checks that no method is in two mixins)
- Two modes in one `Canvas`: screenshot overlay (`show_overlay`, bypass window, focus via `activateWindow`; scene rectangle = image, `fit_overlay()` shows it whole and centered, larger images scaled down via the view, export stays in full resolution) and whiteboard (`board=True`, `show_window`, normal window, very large scene, scene background = color, export = area of all elements). Unsaved detection via `QUndoStack.isClean()`/`setClean()`. Everything that should have a fixed size on screen (handles, snap radius, click tolerance, docking distance) goes through `Canvas.screen_px(n)` (measurement for 1080 px, times `ui_scale`, divided by `zoom()`), so it grows on 4K
- Saving/loading in `document.py`: a normal PNG with the markings, editing data as JSON in the PNG text chunk `griffel` (the old key `slate` from before the rename is still read, `LEGACY_PNG_KEYS`; format/version, raw background as Base64 PNG, elements bottom to top, optional `crop`; `load_document(path, with_crop=True)` returns it as a fifth value). Elements provide `to_dict()`/`from_dict()`, colors as `#rrggbb`. Broken data never crashes: image as background, or skip the element
- History (roadmap 10) in `history.py` (files: list, create, clean up entries) and `canvas_history.py` (when to save, browsing): screenshot mode only, `Canvas.history_path` = current entry (None = off). Saved by a single-shot `QTimer` 1 s after every change of the undo stack and when quitting (`flush_history`); the file is only created with the first change (screenshots without changes never end up in the history), then it also cleans up, but never in the middle of an action (`busy()`: typing, drawing, dragging) and without `render_image()` (that would end the selection and text input). ← → load via `Canvas.replace_content()` into the same canvas. Order = file name (timestamp of the screenshot), not modification time
- Blur: `ShapeElement` with `tool == Tool.BLUR`, block size = `blur_block(width)`; `paint` pixelates the raw image of the scene (`scene.blur_source`, `blur_scale`, set in `Canvas.set_background`), so only the screenshot, not the markings. Hits on the whole area. When saving, `OutputMixin.background_to_save()` returns the raw image with the blurred areas burned in (Ctrl+S, Shift+Enter, history); in memory it stays raw. Screenshot mode only
- Marker: `ShapeElement` with `tool == Tool.MARKER`, `points = [tip, circle center]` (equal = without pointer line), `marker_kind` ("number"/"letter") and `marker_order` (order of placing, saved). The shown number is the position among markers of the same kind (`marker_label()`), so deleting renumbers and undo restores; `scene_.update()` after every undo change
- Labels (text in rectangle/ellipse, roadmap 15, plan `docs/notes/plan-beschriftung.md`): `ShapeElement.label` = `TextElement` as a child item (`set_label`, `layout_label`: wraps at the width, centered, color of the shape), `label.owner` = shape. Not an element of its own: `elements()` and `element_at()` leave it out or return the shape; saved as `label` in the shape's `to_dict`
- Connectors (roadmap 15 part 2, plan `docs/notes/plan-verbinder.md`): line/arrow has `ends = [id, id]` (docked elements, None = free), saved as `ends`, part of `geometry()`. Position derived in `connectors.py` (aims at the center, cut at the outline by bisection, distance `GAP`); `Canvas.update_connectors()` recomputes all after every undo change, so no undo of its own. Deleted target = end free, undo docks again. Docking with the mouse (`canvas_input.dock_end`, `connectors.target_at`), whiteboard only (`dock_target` returns None in screenshot mode): only close to the outline (`DOCK_MARGIN` screen pixels), deep inside stays free; while drawing and at the end point handle, the target is highlighted (`dock_hint`). Moving/rotating the arrow itself releases ends whose shape does not move along (`undock_changes`); `insert_copies` maps `ends` to the new IDs. Text on line/arrow: the same `label` mechanism, centered on the line, horizontal, box in `Canvas.label_box_color()` (whiteboard color or bar color)
- Undo/redo via `QUndoStack`. Every change to the scene is a `QUndoCommand` in `commands.py` and is pushed with `undo_stack.push()`, never executed directly, otherwise it is missing from undo

## Conventions
- Small, working steps. The program must start after every step
- New controls that can be checked by keyboard/mouse get a GUI scenario in `tests/gui/` where possible (harness: `tests/gui/harness.py`, template: `test_overlay.py`). Test there first, then only ask for the manual tests the GUI test cannot cover (flicker, multiple monitors, HiDPI, taste)
- Before every commit, all tests: `python tests/gui/run.py` (all GUI scenarios in their own X server: `test_overlay.py` start via hotkey, focus, sxhkd hotkeys, history; `test_board.py` whiteboard, Ctrl+B, rofi prompt, save/open/discard; `test_help.py` key overview; `test_pointer.py` spotlight and magnifier; `test_blur.py` blur and burning in in the history; `test_marker.py` markers; `test_crop.py` crop and clipboard; `test_select.py` multi-selection, order and rotating; `test_clipboard.py` copying between screenshot and whiteboard, crop with markers, foreign image; `test_label.py` label via double-click into a shape, moving along; `test_text_font.py` monospace via Alt+V (next text, while typing), saved in the history; `test_connector.py` in a screenshot an arrow stays free, in the whiteboard docking to two shapes (highlight), moving a shape; afterwards look at the screenshots in `tests/gui/out/`), `python tests/regress.py` (draws a fixed scene without a screen and compares with `tests/regress_reference.png`), `python tests/test_document.py` (save, load, keep working) and `python tests/test_settings.py` (config values and fallbacks). If the look changes on purpose, rewrite the reference with `--update` and mention it in the commit
- Code stays readable and in separate areas or files: capture, drawing logic/canvas, UI, export. Where new code goes: rule of thumb in `docs/notes/plan-aufteilung.md`
- Shortcuts must work on the US keyboard layout (`us`, variant `altgr-intl`)
- Missing config files or values must never crash, always sensible fallbacks
- No large refactoring without asking. Do not change existing behavior that is not part of the task
- Language: everything in the repo is English (code, comments, docstrings, messages and UI texts, test names, `config.example.toml`, README, `docs/`), except the German working notes in `docs/notes/`

## Known pitfalls
- Never put both `src/` and `src/griffel/` into `sys.path`: every module would then be loaded twice (`export` and `griffel.export` are different objects), and replacing something in one copy misses the other. `tests/test_document.py` checks that no module is loaded flat. Tests always import from `src/`, never an installed griffel
- herbstluftwm: with `showFullScreen()` the desktop background flickered briefly when opening and closing (also without picom, also with a WM rule). That is why the window bypasses the WM. Because herbstluftwm does not know the bypass window, after `activateWindow()` and closing no window had the focus any more; that is why `wm.restore_focus()` gives it back on close. A `grabKeyboard()` avoids this, but also swallows all sxhkd hotkeys (solved that way until 2026-10-01, then replaced)
- With HiDPI the screenshot can be blurry because of scaling (mind the device pixel ratio of the pixmap)
- PySide6: never call `item.parentItem()` on scene elements. If an item only belongs to the scene (e.g. after loading a history entry), the call hands ownership back to Python, and garbage collection deletes it from the scene. That is why labels know their shape via `owner`, checked with `elements.is_label()`
- `run.py` must stay executable (`755`, it is started directly, e.g. via a symlink in `~/.local/bin`). Never write files as a new file and `mv` it over the old one (permissions get lost), change them in place; `git diff --summary` shows a `mode change`
